DIAGNOSIS (what was slow and why)
  - second_ok_eq (3.1 s, the largest): `split_ifs` splits the if-chains on BOTH sides
    (Rust model and Utf8Ref.secondOk), then simp_all runs on every combination.  The two
    chains have the same conditions, so splitting is unnecessary: rewriting
    `if c then ok x else ok y` to `ok (if c then x else y)` (lemma ite_ok) and the U8
    comparisons to Nat makes both sides the same term for simp.  Same one-liner now
    proves every byte-class predicate.
  - loop_spec (2.2 s): three near-copies of the emit code (0, 1, 2 code points), each
    with a manual `rcases x with ⟨xa, back⟩; subst` around Slice.index_mut_usize's back
    function, because step* stops at an `if` in bind position
    (`let (out1, k1) <- if o.n >= 1 then ...`) and at the `let (_, index_mut_back) := x`
    pattern.  Cause in the Rust: the nested `if o.n >= 1 { out[k] = ..; if o.n >= 2 {..} }`
    shares the first write between two branches, so Aeneas hoists it as an index_mut
    with a back function.  Fixed in the Rust (below), not in the proof.
  - unpack_spec + decode_buffer_eq (1.8 + 1.4 s): scalar_tac on div/mod facts with all of
    step*'s hypotheses in context.  scalar_tac costs ~0.2-0.3 s per call in a large
    context even for `x.val < 256`; now one omega call per byte field on Nat equations,
    bounds from hBounds, casts by UScalar.cast_val_eq.
  - A rewrite cycle in the old PendRel (`n = s.length` and, after substitution,
    `s = take n ..`) made simp_all/scalar_tac hit max recursion as soon as the proof was
    driven by step* (which substitutes).  PendRel is now `n <= 3 ∧ s = [b0,b1,b2].take n`
    (no cycle; no longer demands that unused bytes are 0 -- nothing needed that).

RUST: what changed and why
  1. decode_buffer's writes moved into
       fn write_out(out: &mut [u32], k: usize, o: Out) -> usize {
           match o.n { 0 => k, 1 => { out[k] = o.c0; k + 1 }
                       _ => { out[k] = o.c0; out[k + 1] = o.c1; k + 2 } } }
     and the loop body is `let o = step(p, input[i]); k = write_out(out, k, o); ...`.
     Plain Rust, arguably clearer (one function per job).  Generated Lean: loop body
     31 -> 17 lines, straight-line (no if in bind position); write_out is 3 match arms of
     Slice.update (no index_mut_usize / back function).  Effect on the proof: the three
     loop cases and the rcases/subst dance disappeared.  An early-return version
     (`if o.n == 0 { return k; } out[k] = ..; if o.n == 1 ..`) still produced the hoisted
     index_mut_back; the `match` did not.
  2. The one-boolean helper functions (is_lead_multi, vs2, vsp2, vs3, vsp3, vs4) were
     KEPT, after testing the alternatives with this Charon/Aeneas nightly (scratch, not
     shipped):
     - inlining `is_lead2(b0) && second_ok(b0, b)` and the `||` chain into step's `if`
       for the one-pending case: that branch of `step` grows from 9 to ~50 lines, the
       continuation (hold / bad_pending) duplicated 5 times, with re-tests of already
       known Bools (`if b1 then if b2 ..` inside the `else` of `if b2`);
     - `match b { 0x00..=0x7F => .., 0xC2..=0xF4 => .., _ => .. }` in step_fresh: also
       duplicated continuations plus a dead `0 <= b` branch; `matches!(b, 0x80..=0xBF)`
       in is_cont is fine (a single tail expression).
     The rule that holds: a compound condition is fine as a function's tail value and
     duplicates code when it guards a branch with a continuation.  The helpers also
     mirror Utf8Ref's isVS/isVSP definitions one to one, so each gets a one-line spec;
     a skilled user would write them anyway.  Gain from changing them: negative.
  3. Panic handler: see WASM.
