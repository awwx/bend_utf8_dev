VERDICT
  The claim holds. DecoderProofs.verified : Boundary.Verified checks with axioms
  [propext, Classical.choice, Quot.sound] only, and the proof is about the Lean that
  Charon+Aeneas generate from the committed src/lib.rs (regenerated byte-identical for host
  and wasm32; 5 of 5 semantic mutations make the proof fail). Boundary.lean is a sound,
  non-vacuous statement. check.sh has some gaps (below), none of which is exploited now.

  What a user of the generated functions may rely on (in the Aeneas model of the safe Rust):
  - decode_start_state returns (no panic/divergence) a u32 start state.
  - For any state value obtained from decode_start_state followed by any sequence of
    decode_buffer calls, any input slice, and any output slice with
    out.len >= 2 * input.len, decode_buffer returns normally (no panic, overflow,
    out-of-bounds, divergence) a new state and a count k; out'[0..k) holds exactly the
    code points (one u32 each) that a spec-correct stream decoder returns for that input;
    out'[k..) is unchanged; out' has the same length.
  - decode_done with such a state and out.len >= 1 returns normally, writing the
    spec-correct final text (0 or 1 code points) to out'[0..k), rest unchanged.
  - The decoder D is existential but constrained by the spec's Decoder.Correct (unmodified;
    utf8_decodes + safe + prompt), so concatenated outputs are the spec decoding of the
    concatenated input for every split, and each call returns exactly the "resolved"
    prefix. The witness is Utf8Pure.RefDecoder / RefDecoder_correct.
  Nothing is promised for states not produced by the decoder, nor for output slices shorter
  than 2*input.len (even if the text would fit).

2. THE BOUNDARY STATEMENT (lean/Boundary.lean, 69 lines)
  - Uses Decoder and Decoder.Correct from Utf8Laws unmodified; mentions no proof internals
    (only Aeneas library names, decoder.* generated functions, and Utf8Laws).
  - Realizes: ∃ R, (start relates) ∧ (∀ s v input out, R s v → 2|in| ≤ |out| → ∃ v' k out',
    decode_buffer = ok ... ∧ R s' v' ∧ WritesText) ∧ (decode_done similarly). Quantifier
    order is right; R must hold at start and is preserved by every call, so every state
    reachable from start is related, and Correct only constrains D along feeds from D.start
    -- exactly the reachable states. An empty-beyond-start R is impossible because
    preservation must produce R s' v'. Preconditions are satisfiable (out of length 2|in|).
    decode_done is constrained (WritesText with D.decode_done s), and Correct uses D's
    decode_done. No vacuity found.
  - `= ok` is meaningful: Result is an ITree with ok/vis(fail)/div distinct; `loop` is a
    partial_fixpoint and the proof uses loop.spec_decr_nat (termination measure), so
    "never fails or diverges" is stated and proved.
  - WritesText pins location and length: k = |t|, |out'| = |out|, map codePoint (take |t|
    out') = t, drop |t| out' = drop |t| out. So "only the first k positions are written"
    IS stated. The bound |t| ≤ 2|in| is NOT stated, only implied (instantiate out with
    length exactly 2|in|; the text does not depend on out). Likewise |done text| ≤ 1.
  - byte/codePoint are exact (UInt8.ofNat / UInt32.ofNat of in-range values).
  - Usize width is abstract in the Aeneas model (System.Platform.numBits ∈ {32,64}); the
    proof is generic, so it covers wasm32. No length bound beyond the model's |slice| ≤
    Usize.max is needed.
  - Not stated (and fine to leave out): that outputs are Unicode scalars (follows from the
    spec), behaviour on foreign states, aliasing (impossible in the value model; the shim
    must guarantee it).

4. UNVERIFIED PARTS
  Shim (mod shim, excluded via `charon --exclude crate::shim`): three extern "C" exports
  calling exactly the three verified functions. Logic: slice::from_raw_parts(_mut) from
  (ptr,len); store new state through state_out; return k as usize (i32 on wasm32).
  Risks: no check of out_len >= 2*in_len, pointer validity, alignment of out_ptr/state_out,
  or disjointness -- all trusted to the caller. Out-of-contract calls hit a bounds check ->
  panic handler `loop {}`: the Wasm instance HANGS instead of trapping (suggest
  core::arch::wasm32::unreachable()). Release profile (opt 3, LTO, panic=abort,
  overflow-checks off) differs from the dev-profile MIR Charon translates; benign because
  no overflow occurs under the precondition (proved), and indexing checks stay in release.
  decoder.wasm is built by check.sh from the same src/lib.rs (confirmed byte-identical).
  Wrapper (decoder.mjs): (1) grows memory once past the module's own memory and lays out
  IN (64 KiB) | OUT (2*65536 u32) | ST (4 bytes): disjoint, page/4-aligned, outside Rust's
  stack/data (no allocator in the module). (2) Chunks every buffer into <= 65536 bytes, so
  out_len = 2*CHUNK >= 2*len: precondition satisfied; correctness of chunking relies on
  the spec's split independence (proved for D) but the loop itself is unverified; an empty
  buffer makes exactly one len-0 call. (3) State is carried as a JS number; >>>0 on return
  and ToInt32 on the call preserve the bit pattern (states >= 2^31 occur: e.g.
  0x989ff003 after F0 9F 98; spot-tested round trip OK). (4) cpsToString uses
  String.fromCodePoint.apply in 8192-element slices; it would throw on > 0x10FFFF and emit
  lone surrogates for D800-DFFF, but the spec guarantees scalar values, so fine. It reads
  a fresh view of memory each time. (5) decode_done passes OUT_CAP >= 1. Requires buf to be
  a Uint8Array (uses subarray). Not covered by the theorem: everything in (1)-(5),
  the u32->UTF-16 conversion, JS/Wasm ABI marshalling, and the Wasm engine.
  Spot tests I ran: 4-byte char split per byte, 3-byte char straddling the 64 KiB chunk
  boundary, 200 KB worst-case invalid/ASCII mix, pending-at-end -- all match TextDecoder.

5. PROOF QUALITY / MAINTENANCE

  (`f b = ok (refPred (byte b))`), cp lemmas, step refinement (step_eq, 4 cases), writes_one,
  loop invariant LoopInv + loop.spec_decr_nat, StRel via pack/unpack specs, top level.
  Fragile points:
  - 8 warnings: unused simp args; deprecated `if_pos` (line 265) and `List.take_succ`
    (line 285) -- will break on a toolchain bump.
  - loop_spec's three o.n cases (0/1/2) are near-copies with manual
    `rcases x with ⟨xa, back⟩; subst` around Slice.index_mut_usize's back function, and
    step* naming workarounds; sensitive to Aeneas changes in step*/naming.

    different (correct) packing needs proof edits; StRel := ∃ p, PendRel p s ∧ pack p = ok v

    count would shorten it.
