2. NONDETERMINISTIC RULES OF reduce (opsem.v), enumerated
  Genuinely nondeterministic:
  - r_invoke_host_success, r_invoke_host_diverge: host_application is an
    arbitrary relation (host.v: "This can be non-deterministic").
  Nondeterministic in the SHAPE of the result, not in the outcome:
  - rs_trap (trap propagation) overlaps itself under r_label and overlaps
    rs_label_trap / rs_local_trap: e.g. [c1; c2; trap; e] steps to [trap]
    directly or to [c1; trap; e] by r_label around [c2; trap] -> [trap].
    All results are trap configurations (trapped_step_preserved), but they
    are not equal, so literal step determinism fails as soon as AI_trap is
    present.  Hence the fragment excludes AI_trap and the corollary
    handles trapped configurations separately.
  Deterministic in this mechanisation (worth knowing; the Wasm spec is
  looser): memory.grow and table.grow (smem_grow / stab_grow are
  functions; the spec allows a nondeterministic failure, WasmCert fixes
  it), all float operations (numerics.v makes NaN results deterministic),
  SIMD (opaque but total functions app_v*), ref.is_null, select,
  local.set (the frame f' is pinned by its two fields; the default vd is
  irrelevant because the index is checked in range).
  Not nondeterminism but the proof burden: r_label lets a step be
  presented with different contexts (values pushed into the context or
  consumed by the rule; nested labels).  All presentations give the same
  result; proving that is the decomposition work.
  So the fragment excludes floats/SIMD/grow/tables only to keep the case
  analysis small, not because they are nondeterministic.

3. ROUTE CHOSEN AND WHY
  (A)/(C) hybrid: direct proof on reduce, structured like the Iris-Wasm
  proof but reorganised around a "first non-value instruction" view:
   - Fixpoint first_nc (Trapped.v) instead of reasoning on raw list
     equations; its rewrite lemmas let one generic tactic dispatch the
     ~100 rule cases of each induction (this is what made Trapped.v and
     Preservation.v quick: ~5 min each).
   - Focus.reduce_focus_first_gen removes the "rest" of the list from any
     step; what remains is determinism of steps of values ++ [e], by cases
     on e (basic instruction / label / frame / invoke).
  (B) rejected: no completeness theorem exists (section 1).
  The corollary is proved abstractly from three statements, so the
  plumbing to reduce_trans and to the decoder is finished and checked
  now, independently of the remaining determinism proof.

4. THE FRAGMENT (Fragment.v; decidable; see STATUS.txt for the list)
  Preserved by reduction up to trapping, INCLUDING the administrative
  instructions that appear during execution: labels and frames are in
  the predicate recursively, and AI_invoke a is allowed because funcs_ok
  constrains every closure in the store (native, fragment body); s_funcs
  never changes in the fragment (fragment_step_preserved, proved).
  No typing hypothesis is required anywhere.
  The decoder is inside it (decoder_bodies_ok and s0_funcs_ok by
  vm_compute; instruction inventory checked: i32.const, local.get/set,
  i32.add/sub/and/or/shl/shr_u, i32.eq/lt_u/le_u/ge_u, i32.eqz,
  i32.load8_u, i32.store16, if, block, loop, br, br_if; no call, no
  globals, no grow, no tables, no floats, no SIMD, no imports).
  A future module in the same style (integers, globals, one fixed linear
  memory, direct calls, no imports) is covered unchanged; call_indirect
  and tables would need adding (they are deterministic too).

8. PROPOSAL FOR THE USER: stating the unique outcome in Boundary.v
  (Not applied: Boundary.v is the user's file, and another agent is
  working in ../decoder.)  Replace the definition of call_returns and the
  CAVEAT paragraph in Boundary.v by:

    (** Calling function address [a] with arguments [args] in store [s]
        (any host state, any caller frame) returns [res] with store [s'],
        and that is its only outcome: some reduction sequence reaches the
        result; every configuration reachable from the call can still
        reach the result (so no trap and no other result is reachable);
        no reduction sequence runs forever; and the only reachable
        configuration that cannot reduce further is the result. *)
    Definition call_returns hs (s : store_record) (a : N) (args : list value)
               (s' : store_record) (res : list value) : Prop :=
      forall f,
        let c := (hs, s, f, v_to_e_list args ++ [AI_invoke a]) in
        let d := (hs, s', f, v_to_e_list res) in
        reduce_trans c d /\
        (forall c', reduce_trans c c' -> reduce_trans c' d) /\
        (forall run : nat -> host_state * store_record * frame * list administrative_instruction,
           run 0 = c -> ~ (forall n, reduce_tuple (run n) (run (S n)))) /\
        (forall c', reduce_trans c c' ->
           (forall c'', ~ reduce_tuple c' c'') -> c' = d).

  The three new conjuncts are, verbatim, Determinism's
  deterministic_outcome c d (Boundary.v keeps them spelled out so it
  stays self-contained and reviewable without this directory).
