VERDICT
  DOES NOT HOLD AS STATED, because of one off-by-4 constant in Boundary.v. The proof itself is
  real (kernel-checked by rocqchk, only library axioms, every semantic mutation breaks it).
  But the store hypothesis in Realizes is never met by the module's own memory, so every
  per-call guarantee is vacuously true for every store the shipped module can actually have:

    mem_bytes_needed = OUT_addr + out_area IN_max = 65536 + (4*65536 + 4) = 327684 bytes,
    the module's memory is 5 pages = 327680 bytes, with maximum 5 (lim_max = Some 5).

  Proved in probe/Vac.v ("Closed under the global context"):
    s0_not_covered : forall m, nth_error (s_mems s0) 0 = Some m ->
                     ~ (mem_bytes_needed <= mem_length m)
  (s0 is the store that instantiation yields; mem_make_length gives 327680.) Node agrees:
  memory.buffer.byteLength = 327680, and memory.grow(1) throws "Maximum memory size exceeded".
  In WasmCert, mem_grow also respects lim_max, and the module contains no memory.grow. So no
  reachable store satisfies the hypothesis. The theorem only talks about hypothetical stores
  whose memory data is longer than its declared type allows.
  What still holds: instantiation from the empty store is proved (including module_typing),
  the exports exist, and the Decoder satisfies the spec laws. The proof shows correct behaviour
  on memories of >= 327684 bytes.
  Practical risk is low. By my reading of the code, a call writes at most 2*len+2 output bytes
  (one UTF-16 unit per input byte, plus at most one extra unit for bytes carried over from an
  earlier call), so it never touches [327680, 327684). The difftest and my spot tests pass.
  But this is not proved.
  The gap is not purely cosmetic. A module that also wrote 2 bytes at OUT+4*len after its loop
  would still satisfy Boundary.v: the write is inside out_area, and mem_holds only constrains
  the text prefix. Yet that module traps on every full 64 KiB chunk, which is exactly the
  chunk size decoder.mjs uses.
  Fix (not applied): make the layout fit the memory. Options: out_area len = 2*len+2 (the real
  bound), or mem_bytes_needed <= 5 pages with IN_max lowered, or a 6-page memory. The
  re-review of Boundary.v and its hash pin would need to be redone.
  Everything else checked holds, with caveats listed below.

2. BOUNDARY.V, READ HOSTILELY
  - Store size: VACUOUS for real stores. See the verdict. This is the main finding.
  - Existential D: tied to Decoder_correct, the spec's three laws unmodified (the hash of
    spec-rocq/Utf8Laws.v is pinned; the pure-rocq copy is cmp'd). The witness is RefDecoder.
  - Existential R: no degenerate R works. start must give an R-related value, every decode must
    produce R st' v' for D's own next state, and the output must equal D's text for that st.
    An R relating everything would force the module's output to be independent of the state.
    An empty R contradicts start. R need not be functional; that is harmless.
  - s0/inst/addresses: instantiate empty_store decoder_module [] (s0, frame [] inst0, []) is
    proved via interp_instantiate (vm_compute) plus the library's soundness lemma
    interp_instantiate_imp_instantiate. The relational instantiate includes module_typing
    (validation), import typing and alloc_module, so the existential is genuinely inhabited.
    The export addresses come from inst0's export list.
  - Store quantifier: s_funcs = s0's, memory at a_mem of any contents and type, >= 327684
    bytes; globals, tables etc. arbitrary. The module has no globals, tables or data.
    * A store after a call: the result store is store_with_mem s a_mem m' with mem_frame (same
      type and length), so the next call's premises hold again. Sequences are covered (modulo
      the size bug).
    * Host overwrote the input area: covered, since memory contents are arbitrary.
    * NOT covered: a store holding other modules' functions (s_funcs must EQUAL the
      single-module list). Node's store is the engine's, so this is a modelling decision
      (REPORT item 3 says so).
  - store_with_mem: seq.set_nth with default m'. a_mem = 0 exists, so it replaces in place; the
    padding case never arises.
  - mem_frame / mem_holds: the output bytes [OUT, OUT+|utf16le t|) are pinned exactly. The rest
    of the output area [.., OUT+4len+4) is unspecified (may be garbage). Everything outside it
    is unchanged, along with memory length and type and the rest of the store.
  - Lengths: decode returns the number of output BYTES (lg 3 - OUT), the wrapper passes it as
    a Uint8Array length, and done does the same. Consistent. i32_of_nat cannot wrap: len <=
    65536 and output <= 262148 by the frame.
  - call_returns (checked and holds as worded): for all caller frames f, reduce_trans c d; every
    c' reachable from c still reaches d; no run : nat -> cfg with run 0 = c and a reduce_tuple
    step at every n. That is the correct "no infinite run". The host state is the same hs in d
    (not allowed to change). "No trap" is implied: a reachable trapped configuration cannot
    reach values (Trapped.v, see 3). "Forall f" is fine because a native invoke ignores the
    caller's frame. One thing not stated: the call configuration's frame f is unrelated to
    inst0. That is irrelevant for AI_invoke.
  - utf16_units / utf16le: correct UTF-16 for scalars (0xD800 + (n-0x10000)/0x400, 0xDC00 +
    mod). Lone surrogates would map to one unit; values above 0x10FFFF to garbage. The spec
    guarantees outputs are scalars or U+FFFD (decodes_first_scalar via begins_with_scalar, or
    replacement_char). The decoder's texts are constrained through safe/decodes, so this is
    not an issue.
  - Limits: IN_max = 65536 per call (enforced only by the wrapper's chunking). The out area
    4*len+4 is an over-approximation by about 2x (real bound 2*len+2); that slack is what
    breaks the 5-page fit.
  - NOT promised: anything for inputs > 65536 per call (wrapper's job); anything about
    i32 values not produced by the module; contents of the output area beyond the text; other
    modules in the store; the real (5-page) store, as above.

DECISIONS THE USER SHOULD KNOW ABOUT (design level)
  - Memory layout: input up to 64 KiB at address 0, output after it. The specification
    reserves 4 output bytes per input byte plus 4, which does not fit the module's fixed
    5-page memory. As written, the guarantee therefore applies to no real instance (must be
    fixed).
  - Each call gets at most 64 KiB of input; larger buffers are split by the unverified wrapper.
  - The module is assumed to be alone in the Wasm store (no other modules' functions).
  - Decoder states are opaque 32-bit values. Only values the module returned are promised to
    work; old states stay valid.
  - Output is UTF-16LE in memory. Bytes in the reserved area beyond the returned length are
    unspecified; nothing outside it changes.
  - Every call has exactly one outcome: it returns, with no trap and no infinite run, and does
    not touch the host.
