THE 32-BOOLEAN CODE POINT RECORD (evidence about the spec's representation)
  Every place it cost something, over all sessions:
  - Kernel, decoder: the Qed of step_case_complete2 (and 3, 4) does not finish without
    an opacity hint (killed after > 2 min in this pass; > 60 s in session 2), although
    the tactic script runs in about a second.  The kernel unfolds seq_cp s =
    U32_of_N (seq_value s) into a U32_bits record of 32 N.testbit's of a symbolic number
    while checking a conversion.  Making either seq_cp or U32_of_N opaque suffices
    (tested separately, 2.3 s each).
  - Pure layer: encoding_form destructs a U32 into 32 booleans and splits on the shape
    bits (~1.9 s, about 30 cases); U32_to_N_inj peels 32 bits; U32_to_N_bound
    generalizes 32 b2n's; yesterday's pass replaced an enumeration over all scalars
    (Utf8Check.v, 509 s) that existed because of the record.
  - Not the record (measured): Decode.v and utf16le_cp_len (N / Z literal arithmetic
    under simpl), NonVacuity.v (cbn of the module term).
  - The decoder proof never needs the bits: every use goes through U32_to_N, i.e. the
    numeric value.  A spec with U32 as a bounded N (or Z) would remove the whole class.
  What was done: one sealed interface instead of a per-file workaround.  The pure layer
  already had the numeric interface (seq_cp_value, seq_cp_value1..4; now also
  seq_cp_bound in Utf8StepFacts.v); `Global Opaque seq_cp` at the end of
  pure-rocq/Utf8Proofs.v (after every proof there) makes every downstream file use it.
  The decoder's `Local Strategy opaque [seq_cp U32_of_N]` is gone; there is no
  Strategy/Opaque left in the decoder.  (Opaque changes only the order in which the
  kernel unfolds, not what it accepts; a non-Local Opaque was checked to survive
  Require.)  U32_of_N itself is the spec's and stays transparent.

  - One central case lemma: step_case_complete2/3/4 were near-copies (diff: the list
    literal and the cp_code lemma).  Now step_case_complete b1 r b takes the cp_code
    result as a hypothesis and the three named cases are one-line instances (names and
    statements kept; they are printed in check.expected.txt).
  - Every file has a header listing its exports and where its inputs come from.
    Style rule (stated in STATUS): files that touch Wasm use ssreflect, like WasmCert-Coq;
    pure files use stdlib tactics.  Two consequences recorded in the headers: `++` is
    seq.cat under ssreflect and List.app in the pure layer (Decode.v keeps a one-line
    utf16le_cat for that reason), and named arguments `(x := t)` only work for implicit
    arguments, so the pure lemmas are called positionally.
  - Fragility: wr_app's `rewrite O2; [lia|]` relied on the order of the generated side
    goal; now `rewrite (O2 q ltac:(lia))`.  The case lemmas' `rewrite ...; try (apply
    small_const; lia)` patterns are order-independent.  No other bracketed side-goal
    selection after a conditional rewrite remains (grep).
  - Instruction-order dependence: not removed (not at reasonable cost in this box).
    STATUS.txt, "WHAT A CODE EDIT TO Module.v REQUIRES", says what an edit costs: the
    code is factored into named pieces with one lemma each, so an edit inside a piece is
    repaired in that lemma; the case lemmas only chain them.
