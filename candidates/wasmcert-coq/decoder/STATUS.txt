    exists D, Decoder_correct D /\ forall hs, Realizes hs D: the module's exports start /
    decode / done implement a decoder satisfying the spec's streaming laws, through the
    state representation and the memory layout (input <= 64 KiB at 0, output at 64 KiB,
    at most 2*len+2 bytes written, nothing else changed); each call's result is its only

    result, so the memory this claim talks about is the memory the guarantees are about.

WHAT A CODE EDIT TO Module.v REQUIRES
  The case proofs run the code instruction by instruction (wp_step) and name locals by
  position, so any change to step_code's instruction sequence or local numbering breaks
  the matching lemma in StepEmpty/StepPending/StepComplete.v (and Decode.v for the loop,
  Exports.v for start/done).  The code is factored into named pieces (Module.v:
  emit_fffd, emit_cp, empty_code, range_code, len_code, cp_code, pending_code, ...), and
  each has its own lemma (emit_fffd_ok, emit_cp_ok, empty_code_ok, range_code_ok,
  len_code_ok, cp_code_ok2..4, ...), so an edit inside one piece is repaired in that
  lemma; the case lemmas only chain them.  DetInstance.v and Instance.v recompute by
  vm_compute and need no edit; Binary.v and decoder.wasm are regenerated by make.
