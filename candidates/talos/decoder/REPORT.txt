1. THE THEOREMS
  Target (Boundary.lean, unproved):
    ShippedModuleCorrect : ∀ m, Decoder.Wat.decodeForVerification printedWat = .ok m →
                             ∃ D : Decoder, D.Correct ∧ Realizes m D
    printedWat := include_str "decoder.printed.wat" (= wasm-tools print decoder.wasm,
    re-derived by check.sh).  Realizes m D := ∃ R, StartOk ∧ BufferOk ∧ DoneOk;
    each is a Talos `RunsExportWith` (total correctness in the small-step `Step`
    relation: a finite trace to `.done`, so no trap and no divergence) from
    `storeWith m mem` = Talos `Module.initialStore` with an arbitrary memory
    (any bytes, pages <= 65536), with i32 arguments/results, input bytes read by
    `bytesAt`, text written as little-endian u32 code points (`textBytes`), and
    the final store = storeWith m mem' where mem' differs from mem only inside the
    written output (`sameOutside`).  Because the module has no globals/tables/
    imports and every export leaves the store in this form, this covers every
    sequence of calls on one instance, including JS writes and memory.grow.
  Proved (for the literal `decoderModule`; decoderModule_decodes links it to the
  printed text):
    start_ok    : StartOk with R := Rel (already the boundary shape).
    stepM_nil   : per-byte model = RefDecoder.step when nothing is pending.
    done_runs   : decode_done(v,out) returns out / writes 0xFFFD and returns 4+out.
    buffer_runs : decode_buffer(v,inp,len,out) under inp+len <= out,
                  out + 8*len <= pages*65536, out + 8*len < 2^32: returns
                  [(runM ..).1, (runM ..).2.1], final store storeWith (runM ..).2.2,
                  runM = left fold of the model `stepM` over bytesAt mem inp len.
  #print axioms (Axioms.lean): propext, Classical.choice, Quot.sound for all.

5. SCALING
  - What made it scale: (i) `Reach` hides traces; (ii) a symbolic-execution
    tactic (`wauto`: try every instruction rule, normalize if-encoded booleans,
    `split` on symbolic `if`s, apply call lemmas) proves a function's call lemma
    in 2-4 lines whatever its number of paths; (iii) call lemmas stated for an
    arbitrary caller context make functions compose without re-tracing, so cost
    is per function path, not per program path.  Talos's own Wp layer was not
    usable (it targets the old big-step `exec` and needs Mathlib).
  - Costs: elaboration time grows with the number of paths and with the size of
    the goal (callee bodies are carried in control frames); 30-50 s for a
    function with ~5 paths.  maxHeartbeats had to be disabled.
  - Loops still need a hand-written loop-head configuration and an induction
    (as in the spike), about 100 lines for this loop.
  - For a larger component the Wasm side looks manageable with this machinery;
    the kernel-checked decode and the per-function elaboration time are the
    limits.  The model-to-spec refinement is ordinary Lean and is where most of
    the remaining effort is.

6. WHAT PUSHED THE IMPLEMENTATION
  - Mirroring Utf8Ref function by function ($vs/$vsp/$cp re-extract bytes and
    re-check ranges on every byte, $step calls both $vs and $vsp) is slower than
    a DFA but keeps the refinement proof shallow.  A table-driven decoder was
    avoided because tables in memory would have to be framed in every lemma.
  - Output as UTF-32 rather than UTF-16 keeps the Wasm and the layout statement
    simple but moves the UTF-16 conversion (String.fromCodePoint) into the
    unverified wrapper and costs 4 bytes per code point.
  - No pressure from Talos itself: every instruction used (multi-value results,
    recursion, early return inside if) is modelled.
