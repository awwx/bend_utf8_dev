WHAT REPLACED THE ENUMERATIONS
  checkA (all 1,112,064 scalars: encoding of U32_of_N n, value round trip) and
  checkB (all valid prefixes: value is a scalar, re-encodes, completion) are gone.
  Utf8Bridge.v instead has a few central lemmas:
  - U32_to_of : n < 2^32 -> U32_to_N (U32_of_N n) = n.  Via a helper
      low_bits k j n (value of bits j..j+k-1) = (n / 2^j) mod 2^k, by induction
      with N.div_pow2_bits, N.bit0_mod, N.Div0.mod_mul_r.  U32_to_N_inj by
      peeling b2n b + 2 * x = b2n c + 2 * y 32 times; U32_of_to from those
      (was 528 rewrites, 8 s; now 0.1 s).
  - utf8_form s n : the UTF-8 layout of n (Unicode Table 3-6 as arithmetic: the
      length chosen by the range of n, lead byte >= C0/E0/F0, continuation bytes
      80..BF, n = ((b1 - lead) * 64 + (b2 - 0x80)) * 64 + ...).
  - encoding_form cp : encoding cp is Some s with utf8_form s (U32_to_N cp), or
      None and U32_to_N cp >= 0x200000.  Proof: split on exactly the bits the shape
      patterns test, in the order the compiled matches test them (about 30 cases,
      not 2^32), rewrite bytes by bN_bit8 (weighted bit sum), lia.  ~2 s.
  - utf8_form_unique : a number has one layout.
  - vs_form / form_vs : vs s = true iff s is the utf8_form of seq_value s and that
      value is a scalar.  Case split on byte *classes* (seq_len_cases, lo2_hi2_cases),
      then the mods in seq_value become subtractions (mod_offset) and lia closes it.
  - encodes_iff (same statement as before) follows in a few lines;
    pending_completion (same statement) by the same class split.
  Utf8Proofs.v kept its structure (laws, step machine invariant, streaming laws,
  downstream lemmas); the bridging section shrank to two corollaries of
  encodes_iff, and the byte-table lemmas moved to Utf8Bridge.v (re-exported, so
  downstream short names still resolve).

WHAT A FURTHER PASS COULD DO
  - Utf8Bridge.v is 9 s; the big items are encoding_form (~2 s, lia per leaf with
    N subtraction), form_vs / vs_form / pending_completion (~1.5 s each).  Stating
    utf8_form without N subtraction (or with digits as separate variables) and
    clearing irrelevant hypotheses before lia would likely halve it.
  - utf8_form could replace the hand-written range table (seq_len/lo2/hi2) as the
    single description of valid sequences, if downstream agreed; Utf8Ref.v was
    kept byte-identical here because the WasmCert decoder unfolds its definitions.
  - A machine-friendly state view (pending count, partial code point, next-byte
    bounds) for the Wasm refinement is still not provided (as before).
  - Suggested (not done, statement kept): seq_cp_value1..4 could be derived for
    downstream directly from utf8_form (form_vs) in the linear "b - 0x80" form,
    which matches shift-and-mask code better than the mod form.
